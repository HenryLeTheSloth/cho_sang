# M4 Giỏ quà Fabric: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Load skill `react-router` trước khi đụng route/root; `prisma-client-api` trước khi viết query. **Không** load `prisma-orm-setup`.

**Goal:** Khách tự xếp giỏ quà biếu ở `/gift` (1 vỏ giỏ, 12 món có ảnh tách nền, chạm để thêm, kéo/xoay/phóng to trên canvas Fabric, tối đa 10 món, lời chúc ≤120 ký tự), bấm "Thêm vào giỏ hàng" thì giỏ quà thành **một dòng** "Giỏ quà · N món" trong drawer và checkout (chỉ là `<img>`, không tải Fabric), đặt COD được, kho trừ từng món và vỏ giỏ, trang đơn nhóm món theo giỏ quà kèm ảnh. Layout gửi lên với pid lạ hoặc quá 10 món bị server từ chối. Fabric chỉ có ở `/gift`.

**Architecture:** `layout [{pid,x,y,s,r}]` là nguồn duy nhất (spec mục 2): món suy ra bằng cách đếm `pid`. `/gift` (loader + action) tạo `GiftBundle` sau khi zod kiểm layout/lời chúc/ảnh và DB kiểm mọi pid có `cutoutUrl`, rồi thêm id vào cookie `b`. Ảnh xem trước (webp ≤60KB, tạo ở client) được phát bằng resource route `/gift/preview/:id`, nên drawer/checkout/đơn chỉ hiện `<img>`. `getCartView` trả thêm `bundles` (giá = vỏ giỏ + từng món, đọc lại từ DB); giỏ quà đi vào `placeOrder` thành các `OrderLineInput` có `bundleId` (vỏ giỏ + từng món), `aggregateQty` gộp kho theo sản phẩm. Thao tác giỏ quà trong drawer đi chung fetcher "cart" của M2 và được lần gửi sau mang theo. Fabric nằm trong `app/lib/gift-canvas.client.ts`, chỉ `import()` động trong `useEffect` của `/gift`.

**Tech Stack:** react-router 8.4.0 (`useFetcher` + `flushSync`, resource route trả `Response` ảnh, `.client.ts` module), Prisma 7.10.0 (`GiftBundle` có sẵn từ M0, P2003), zod 4.6.7 (`transform` + `ctx.addIssue` + `pipe`), sharp 0.35.5 (`trim`, webp có alpha), **fabric 7.4.0 (cài mới ở Task 5, có trong bảng stack spec; từ chối install script của `canvas`)**, `danielgatis/rembg` (Docker, chạy MỘT lần, offline, không thành dependency), vitest 5.0.4, @playwright/test 1.64.0, playwright-cli (global) để chụp ảnh.

**Spec:** [docs/superpowers/specs/2026-10-14-cho-sang-grocery-design.md](../specs/2026-10-14-cho-sang-grocery-design.md): mục 2 (dòng "Fabric: thiệp hay giỏ quà", "Mô hình dữ liệu giỏ quà", "Giỏ hàng"), mục 3 MVP ("Giỏ quà Fabric `/gift`", "Cart drawer … dòng giỏ quà có ảnh preview", "Admin: chi tiết đơn có món theo nhóm giỏ quà", "Home: Đường vào `/gift`"), mục 4 (palette, UX, reduced motion), mục 5 (GiftBundle, `GIFT_MAX_ITEMS=10`, cookie `b`, route `/cart` intent `add-bundle`/`remove-bundle`, `/gift`, quy tắc checkout gộp kho, chunk Fabric ≤130KB chỉ ở `/gift`), mục 6 (dòng M4 + DoD), mục 9 (cut-out tách nền một lần offline). Roadmap: [2026-10-14-cho-sang-roadmap.md](2026-10-14-cho-sang-roadmap.md): hợp đồng module (`catalog.ts` thêm `cutout`), spike 2 (deny `canvas`), ruling M0 (field mới từ catalog phải vào object `update` của seed), mọi mục **"Chuyển sang M4"** ở "Kết quả M1/M2/M3" (bắt buộc, bảng phủ ở cuối phần Decision) và `.superpowers/agents/m3-final-review.md` mục "M4 carry-overs".

## Global Constraints

- Phiên bản ghim exact (`.npmrc: save-exact=true`). **Dependency mới duy nhất: `fabric@7.4.0`** (`npm i -E`, Task 5). Nó kéo optional `canvas@3.2.3` (node-canvas, có install script) và `jsdom@26.1.0`: **chạy `npm install-scripts deny canvas`** ngay sau khi cài (roadmap spike 2), `allowScripts` có `"canvas": false`. rembg **không** vào package.json (chạy bằng `docker run` một lần, Task 1). zod chỉ import từ file `.server.ts`.

Tổng đơn dùng lại `cartTotals()` (giỏ quà là một dòng `{ priceVnd, qty: 1, stock }`), và `placeOrder` vẫn so tổng với `expectedTotalVnd` như M3.
- Kho: giữ nguyên `placeOrder` của M3 (gộp theo sản phẩm, `updateMany … stock >= q` theo id tăng dần). Vỏ giỏ là sản phẩm `isGiftBase` (ẩn khỏi collection) nhưng **vẫn đặt được**: `insertOrder` chỉ lọc `isActive` (đừng đổi sang `visible`).

## Quyết định (Decision) ở những chỗ spec để ngỏ

1. **Decision: 12 món có ảnh tách nền** = `xoai-cat-hoa-loc`, `cam-sanh`, `chuoi-gia`, `bo-034`, `trung-ga-ta`, `banh-mi-sandwich`, `dau-an-dau-nanh`, `duong-mia`, `gao-st25`, `pho-mai-lat`, `toi-ly-son`, `ot-hiem`. Chọn theo kết quả rembg thật (spike 9): chỉ ảnh có vật thể tách rời trên nền trơn mới tách sạch; ảnh đầy khung (bưởi, thanh long, cà chua bi, hạt điều, nho) hỏng. `tao-envy` tách đẹp nhưng là món **hết hàng** cố ý của demo nên không chọn. Trang `/gift` chỉ hiện món có `cutoutUrl`, đang bán, còn hàng.
2. **Decision: cut-out tạo bằng `danielgatis/rembg` ghim digest, model `isnet-general-use`**, chạy một lần trong Docker (không pip trên máy này). Model mặc định `bria-rmbg` (1GB) bị OOM-kill (exit 137). Kết quả là PNG trong suốt, cắt sát viền + thu về cạnh dài 600px, lưu `seed/images/cutouts/<slug>.png` (spec mục 9). Seed chuyển thành `uploads/products/<slug>-cutout.webp` (cạnh dài 400px, giữ alpha, ~15–38KB), `Product.cutoutUrl = "products/<slug>-cutout"`, và `cutoutUrl` được thêm vào object `update` của seed (ruling M0). Regex `/uploads` thêm `cutout` vào nhóm hậu tố. Catalog đánh dấu `cutout: true`; thiếu PNG thì seed dừng với lời nhắn rõ.
3. **Decision: vỏ giỏ vẽ bằng path trên canvas**, không dùng ảnh tách nền của vỏ giỏ. Ảnh `gio-may-qua-bieu` hiện có là giỏ đã đầy trái cây (rembg ra cả trái cây), không làm được "vỏ rỗng". Quai + miệng sau là `backgroundImage` (dưới các món), thân trước là `overlayImage` (trên các món), nên món trông như đặt trong lòng giỏ. Ảnh sản phẩm của vỏ giỏ không đổi.
4. **Decision: ảnh xem trước webp 480×480, quality 0.8** (hạ dần 0.6 → 360px khi vượt trần); 10 món + lời chúc đo được **25,7KB** (spike 7). Safari không mã hoá được webp (`toDataURL("image/webp")` trả PNG): client khi đó xuất **jpeg** cùng cỡ. Server nhận `data:image/(webp|jpeg);base64,…`, ≤60KB, rồi đọc **header** bằng `sharp().metadata()` (không giải nén): định dạng phải đúng tiền tố và cả hai cạnh ≤`GIFT_PREVIEW_PX` (480). Một webp 2,5KB có thể khai báo 8000×8000 (≈256MB khi trình duyệt giải nén) và làm treo tab của chủ shop ở trang đơn/admin (cổng plan M4, thay đổi 2). Cổng plan đã duyệt jpeg như nhánh dự phòng phát hiện theo tính năng (không dò UA); spec mục 5 được sửa theo (Task 7 Step 7).
5. **Decision: ảnh xem trước được phát bằng resource route `/gift/preview/:id`** (giải mã base64 thành byte, `Cache-Control: private, max-age=31536000, immutable` vì GiftBundle không đổi), thay vì nhét data URL vào dữ liệu loader. Root loader chạy lại sau mỗi lần điều hướng và mỗi lần bấm giỏ: 10 giỏ × 60KB data URL sẽ đi kèm mọi lần. Route kiểm lại `isPreview` (tiền tố + kích thước) trước khi phát (cổng M3 "render preview sau khi kiểm"). id là "chìa khoá" duy nhất của ảnh nên **không** dùng `cuid()` của Prisma (cuid v1: timestamp + bộ đếm + fingerprint đọc được từ chính id của kẻ tấn công, phần ngẫu nhiên ≈41 bit từ `Math.random()`): `createBundle` tự đặt `id = "c" + randomBytes(12).toString("hex")` (96 bit CSPRNG, vẫn qua `z.cuid()`, schema cookie và regex route). Response có `X-Content-Type-Options: nosniff` (byte do khách gửi, phát từ origin của shop). id chỉ nằm trong cookie giỏ (ký, httpOnly) và trang đơn đã qua `canViewOrder`. Cổng plan duyệt mô hình "URL là chìa khoá"; route map của spec thêm dòng này (Task 7 Step 7).
6. **Decision: toạ độ layout** = tâm món theo tỉ lệ 0–1 của khung vuông logic 400×400 (`x`, `y`), `s` = tỉ lệ so với cỡ lúc thêm (cạnh dài 120/400), `r` = góc 0–360°, làm tròn 3 chữ số. zod chặn `x,y ∈ [0,1]`, `s ∈ [0.2,5]`, `r ∈ [−360,360]`. Khung CSS co giãn theo màn hình (Fabric tự quy đổi toạ độ chạm), nên cùng một layout ra cùng một ảnh ở 375px và 1280px.
7. **Decision: lời chúc gõ ở `<textarea>` bên ngoài canvas** (bàn phím, trình đọc màn hình, bộ gõ tiếng Việt trên điện thoại đều dùng được), hiện trên canvas bằng `Textbox` không sửa được (`editable: false`), kéo được, không có núm. Server chuẩn hoá NFC rồi mới đếm ≤120 (chữ Việt gõ trên macOS/iOS có thể là NFD). Không có lời chúc thì không có chữ trên canvas.
8. **(Đã thay bởi ruling fix Task 3, xem `.superpowers/sdd/2026-10-15-m4-gift/global-constraints.md` Decision 8: `BundleOp = {remove, add}`, Hoàn tác luôn `add`.)** **Decision: thao tác giỏ quà trong drawer đi chung fetcher "cart" của M2** (cùng lý do M2 Decision 2: một lần gửi mang toàn bộ trạng thái đang chờ). `cartFormData(quantities, bundleOp)` gửi `intent=add-bundle|remove-bundle` + `bundle[]` **kèm các cặp pid/qty đang chờ**; lệnh giỏ quà đang bay được lần bấm + sau mang theo (`pendingBundleOp`), nên bấm + ngay sau khi xoá giỏ quà không làm giỏ quà sống lại (Review Focus 1). "Hoàn tác" xoá giỏ quà: lệnh xoá **chưa về** (`fetcher.state === "submitting"`) thì gửi lại `remove-bundle` không có id đó (huỷ lần trước); còn lại (kể cả lúc `loading`: RR giữ `fetcher.formData` suốt lượt tải lại sau action, `router.js:882`, khi cookie đã mất id) thì `add-bundle [id]` (idempotent). Cổng plan M4 bắt lỗi mất hoàn tác này trên 4G chậm. `add-bundle` chỉ nhận id GiftBundle có thật, không trùng, tối đa 10. `ponytail:` hoàn tác giỏ A đúng lúc lệnh của giỏ B còn bay có thể mất một thao tác (người dùng thấy và bấm lại).
9. **Decision: dòng giỏ quà trong giỏ hàng** = `CartBundle { id, qty: 1, itemCount, priceVnd, stock, shortNames, isWeighed, message, components }`. `stock = 0` khi có món (hoặc vỏ giỏ) tồn kho ít hơn số cần trong giỏ: dòng vẫn hiện, gạch, "Tạm hết X, không tính vào tổng", không vào đơn (đúng M2 Decision 6 / M3 Decision 9). GiftBundle không còn (DB reset) hoặc có thành phần ngừng bán thì bỏ cả dòng (như dòng thường, roadmap Review Focus 3).
10. **Decision: "Mua lại đơn này" thêm lại cả giỏ quà** (cùng GiftBundle: bố cục, ảnh, lời chúc không đổi; giá đọc lại lúc đặt) vào `b` qua `setBundles` (chỉ id còn tồn tại, tối đa 10). Món trong giỏ hết hàng thì checkout báo như Decision 9 (cổng M3 carry-over 7).
11. **Decision: checkout** dựng dòng giỏ quà từ `b`, đưa vào tóm tắt và `total` ẩn; action gửi `[...dòng thường còn hàng, ...thành phần giỏ quà (bundleId)]`; đặt xong xoá **cả `l` lẫn `b`** (`EMPTY_CART`); `takenSlots(now)` chạy **trước** `orderForKey(key)` (Kết quả M3). Lời nhắn 409: món thiếu kho nằm trong giỏ quà ghi "X (có trong giỏ quà) chỉ còn N …"; giỏ quà có món vừa hết ghi "Giỏ quà có món vừa hết hàng (X).". Dòng phụ của giỏ quà ở tóm tắt là lời chúc, hoặc "Gồm vỏ giỏ và các món đã chọn" (không hứa nơ/thiệp: hệ thống không có). `placeOrder` map P2003 **trên đúng khoá ngoại `OrderItem_bundleId_fkey`** (GiftBundle bị xoá giữa lúc xem và lúc đặt) thành `changed` (cổng M3 N4); P2003 của khoá ngoại khác (vd. `userId`) vẫn là lỗi thật (500), không bị nói thành "giỏ đã thay đổi".
12. **Decision: trang đơn** nhóm món: `getOrder` trả thêm `bundles [{id, message, layout}]`, `toOrderView` trả `items` (chỉ dòng thường) + `bundles [{id, message, itemCount, items, totalVnd}]`; mỗi giỏ quà một khối có ảnh 96px (`/gift/preview/:id`), "Giỏ quà · N món", lời chúc, vỏ giỏ + từng món. Vẫn sau `canViewOrder`. M5 admin dùng lại đúng `getOrder` + `toOrderView` này.
13. **Decision: `/gift` sau khi thêm vào giỏ thành công**: xoá bố cục (bắt đầu giỏ mới) và mở drawer để khách thấy dòng "Giỏ quà · N món". Action từ chối trước khi tạo khi cookie đã có 10 giỏ quà (không để lại GiftBundle mồ côi). Nút "Thêm vào giỏ hàng" khoá khi chưa có món, khi ảnh món đang tải lên canvas, khi đang gửi (`flushSync`), hoặc vỏ giỏ hết hàng. Ô chọn món cũng khoá khi đang gửi (món chạm thêm lúc đó sẽ bị xoá cùng bố cục khi gửi xong).
14. **Decision: bố cục 375px**: canvas vuông full bề rộng ngay dưới tiêu đề, **hàng món cuộn ngang** ngay dưới canvas (thấy món hiện lên giỏ khi chạm), rồi "Trong giỏ quà", lời chúc, nút dính đáy. ≥768px: canvas cột trái (dính), lưới 4 cột bên phải.
15. **Decision: không có chuyển động trên canvas** (không `animate`, không hiệu ứng thả), nên `prefers-reduced-motion` được tôn trọng mặc nhiên; hover/transition của nút theo quy tắc toàn cục ở `app.css`.
16. **Decision: hàng cân ký trong giỏ quà vẫn ghi "tạm tính ±10%"** (trang đơn, ghi chú checkout), như dòng thường.
17. **Decision: đường vào `/gift` ở trang chủ** là một thẻ trung tính (`bg-surface`, icon `Gift` trên nền `ink/5`) đặt giữa "Danh mục" và "Khuyến mãi hôm nay", không dùng magenta làm nền.
18. **Decision: người dùng bàn phím/trình đọc màn hình** dùng được trọn luồng (chọn món, bỏ món, lời chúc, thêm vào giỏ) nhưng không di chuyển/xoay được món bằng bàn phím; vị trí chỉ là trang trí, ảnh xem trước dùng vị trí mặc định (cổng plan: duyệt cho MVP, ghi vào danh sách a11y M7). Khung canvas `aria-hidden`; trạng thái "Đang mở khung xếp giỏ…" (`role="status"`) và lỗi tải (`role="alert"` + `CircleAlert`) nằm **ngoài** khung đó, nên trình đọc màn hình biết vì sao các nút chọn món đang khoá.
19. **Decision: `/orders` đếm "món" như lúc đặt**: mỗi dòng thường 1, mỗi giỏ quà 1 (`listOrders` đếm `bundleId: null` + số giỏ quà khác nhau), không phải số dòng `OrderItem` (một giỏ quà 3 loại món từng hiện "4 món").

```ts
/**
 * Một món trên canvas giỏ quà (spec mục 5: layout `[{pid,x,y,s,r}]` là nguồn duy nhất).
 * x, y: tâm món theo tỉ lệ 0–1 của khung vuông; s: tỉ lệ so với cỡ lúc mới thêm; r: góc xoay (độ).
 */
export type LayoutItem = { pid: number; x: number; y: number; s: number; r: number };

// Canvas xuất webp; Safari không mã hoá được webp nên trả PNG, client khi đó xuất jpeg (Decision 3)
const PREVIEW = /^data:image\/(?:webp|jpeg);base64,[A-Za-z0-9+/]+={0,2}$/;

/** Ảnh xem trước hợp lệ: đúng tiền tố, base64 sạch, ≤60KB. Kiểm lúc nhận (zod) và lúc phát ảnh (route preview). */
export const isPreview = (s: unknown): s is string => typeof s === "string" && s.length <= GIFT_PREVIEW_MAX && PREVIEW.test(s);

/** Danh sách món suy ra từ layout bằng cách đếm pid (không lưu `items` riêng: spec mục 2). */
export function countItems(layout: { pid: number }[]): Map<number, number> {
  const count = new Map<number, number>();
  for (const { pid } of layout) count.set(pid, (count.get(pid) ?? 0) + 1);
  return count;
}
```

```ts
    where: { id: { in: ids } },
    select: { id: true, layout: true, message: true, baseProductId: true },
  });
```

```ts
import { useFetcher, useRouteLoaderData } from "react-router";
import type { loader as rootLoader } from "~/root";
import { applyPending, type BundleOp, cartCount, cartFormData, cartTotals, pendingBundleOp, pendingQuantities } from "./cart";

/**
 * Mọi nơi đọc/ghi giỏ đi qua hook này. Một fetcher dùng chung key "cart": lần gửi mới tự huỷ lần trước
 * (trình duyệt bỏ luôn Set-Cookie của lần bị huỷ), nên mỗi lần gửi mang theo MỌI số lượng còn đang chờ.
 * Nhờ vậy bấm nhanh trên nhiều thẻ không mất dòng, và giá trị cuối khớp lần bấm cuối (spike M2, mục 3–4).
 * flushSync: render lại đồng bộ ngay khi submit, để lần bấm sau (dù không chờ) đọc được `pending` mới (spike mục 10).
 * Giỏ quà (M4): thao tác `add-bundle`/`remove-bundle` đang bay cũng được lần gửi sau mang theo, nên bấm + ngay sau
 * khi xoá giỏ quà không làm giỏ quà sống lại.
 */
export function useCart() {
  const cart = useRouteLoaderData<typeof rootLoader>("root")?.cart;
  const serverLines = cart?.lines ?? [];
  const fetcher = useFetcher<{ error: string | null }>({ key: "cart" }); // dữ liệu từ action hoặc clientAction
  const pending = pendingQuantities(fetcher.formData);
  const bundleOp = pendingBundleOp(fetcher.formData);
  const removing = bundleOp?.intent === "remove-bundle" ? bundleOp.ids : [];
  const lines = applyPending(serverLines, pending);
  const bundles = (cart?.bundles ?? []).filter((b) => !removing.includes(b.id));
  const submit = (quantities: Map<number, number>, op: BundleOp | null = bundleOp) =>
    fetcher.submit(cartFormData(quantities, op), { method: "post", action: "/cart", flushSync: true });
  return {
    lines,
    bundles,
    count: cartCount(serverLines, pending) + bundles.length,
    totals: cartTotals([...lines, ...bundles]),
    error: fetcher.data?.error ?? null,
    qtyOf: (id: number) => pending.get(id) ?? serverLines.find((l) => l.id === id)?.qty ?? 0,
    setQty: (id: number, qty: number) => submit(new Map(pending).set(id, qty)),
    removeBundle: (id: string) => submit(pending, { intent: "remove-bundle", ids: [...removing, id] }),
    // Hoàn tác: lệnh xoá CHƯA về (state "submitting") thì gửi lại lệnh xoá không có id này để huỷ nó. Lệnh xoá đã về thì
    // cookie đã mất id dù fetcher.formData còn giữ suốt lúc tải lại ("loading", router.js:882): phải add-bundle (cổng plan M4).
    // ponytail: hoàn tác giỏ A trong lúc lệnh của giỏ B còn bay có thể mất 1 thao tác; người dùng thấy và bấm lại.
    restoreBundle: (id: string) =>
      submit(
        pending,
        removing.includes(id) && fetcher.state === "submitting"
          ? { intent: "remove-bundle", ids: removing.filter((x) => x !== id) }
          : { intent: "add-bundle", ids: [id] },
      ),
  };
}
```

```ts
export async function createGiftCanvas(host: HTMLElement): Promise<GiftCanvas> {
  const el = document.createElement("canvas"); // canvas riêng mỗi lần: StrictMode chạy effect 2 lần không đụng canvas đã khởi tạo
  host.append(el);
  const canvas = new Canvas(el, {
    width: SIZE,
    height: SIZE,
    backgroundColor: "#FFFFFF",
    preserveObjectStacking: true, // chọn món không đưa nó lên trên cùng (che lời chúc)
    selection: false, // không kéo vùng chọn nhiều món
    backgroundImage: basketBack(),
    overlayImage: basketFront(),
  });
  canvas.setDimensions({ width: "100%", height: "100%" }, { cssOnly: true });

  const items = new Map<number, { obj: FabricImage; pid: number; base: number }>();
  const wanted = new Set<number>(); // uid đang chờ ảnh tải: bị xoá trước khi tải xong thì không thêm nữa
  let text: Textbox | null = null;

  return {
    async add(uid, pid, src) {
      wanted.add(uid);
      const img = await FabricImage.fromURL(src);
      if (!wanted.has(uid) || canvas.disposed) return;
      const base = ITEM / Math.max(img.width, img.height);
      const n = items.size;
      img.set({
        ...CONTROL_STYLE,
        scaleX: base,
        scaleY: base,
        left: SIZE * (0.26 + 0.12 * (n % 5)),
        top: SIZE * (0.5 + 0.06 * (Math.floor(n / 5) % 2)) - 0.04 * SIZE * (n % 2),
        angle: (n % 3) * 8 - 8,

      canvas.setActiveObject(img);
      canvas.requestRenderAll();

    remove(uid) {
      wanted.delete(uid);
      const item = items.get(uid);
      if (!item) return;
      items.delete(uid);
      canvas.remove(item.obj);
      canvas.requestRenderAll();
    },
    setMessage(message) {

          pid,

    },
    async dispose() {
      wanted.clear();
      await canvas.dispose();
      el.remove();
    },
  };
}
```

```tsx
}
```
