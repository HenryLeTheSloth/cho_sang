# M5 Admin: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Load skill `react-router` trước khi đụng route/root; `prisma-client-api` trước khi viết query. **Không** load `prisma-orm-setup`.

**Goal:** Chủ shop đăng nhập bằng mã quản trị và vào `/admin`: danh sách đơn đổi trạng thái ngay trên dòng (chờ → đang chuẩn bị → đang giao → đã giao, hoặc huỷ có hoàn kho), mỗi lần đổi ghi đúng cột `*_at` nên timeline của khách cập nhật; chi tiết đơn để soạn hàng, món nhóm theo giỏ quà (soạn theo danh sách món, ảnh giỏ quà chỉ để tham khảo); thêm/sửa/ngừng bán sản phẩm, tải ảnh ≤10MB (ảnh điện thoại) ra đủ 6 biến thể bằng sharp. File không phải ảnh bị từ chối; khách vào `/admin` bị chặn.

**Architecture:** Route layout `/admin` có `middleware` gọi `requireAdmin` (chạy cho cả loader lẫn action con, kể cả request `.data`), và **mọi loader/action con vẫn tự gọi `requireAdmin`** (loader của layout không chạy khi gửi action con: spike 1) trước `readForm`. Đổi trạng thái là một `updateMany` có điều kiện `status = <trạng thái admin đang thấy>` ghi cột `*_at` của đúng bước kế tiếp (`advanceOrder`), huỷ dùng lại `cancelOrder` với tham số `from`. Upload đi qua chính `readForm` (đọc theo luồng, trần 11MB, `Response.formData()` tách multipart: không thêm thư viện), kiểm byte đầu + `sharp.metadata()` có trần điểm ảnh, rồi `saveSquareImage` (đã gia cố: tên phải là slug, giải mã một lần, mã hoá xong cả 6 biến thể mới ghi). Key ảnh vẫn là `products/<slug>`, thêm `?v=<mã>` sau mỗi lần tải ảnh để cache 7 ngày của `/uploads` không giữ ảnh cũ.

**Tech Stack:** react-router 8.4.0 (route lồng nhau, `middleware`, `useFetcher` mỗi dòng, `useRevalidator`, `shouldRevalidate`), Prisma 7.10.0 (`updateMany` có điều kiện, migration `migrate diff` + `migrate deploy`), zod 4.6.7, sharp 0.35.5 (`limitInputPixels`, `metadata()`), vitest 5.0.4, @playwright/test 1.64.0, playwright-cli (global) để chụp ảnh. **Không thêm dependency nào.**

**Spec:** [docs/superpowers/specs/2026-10-14-cho-sang-grocery-design.md](../specs/2026-10-14-cho-sang-grocery-design.md): mục 1 (pitch "chuyển sang admin đổi trạng thái đơn, quay lại thấy timeline của khách cập nhật"), mục 2 (Auth: admin chỉ bằng `ADMIN_PASSCODE`; Hàng cân ký: admin nhập cân để "Nếu kịp"), mục 3 MVP "Admin" + "Nếu kịp" 4, mục 4 (palette, UX không nhượng bộ), mục 5 (Product, Order `*_at`, quy tắc huỷ hoàn kho, route `/admin/*` layout + `requireAdmin`, ảnh 320/640/1080 × AVIF+WebP), mục 6 (dòng M5 + DoD). Roadmap: [2026-10-14-cho-sang-roadmap.md](2026-10-14-cho-sang-roadmap.md): hợp đồng module (`saveSquareImage`, key `products/<slug>`, `requireAdmin`, `placeOrder`), mọi mục **"Chuyển sang M5"** ở Kết quả M0/M1/M3 (bảng phủ ở cuối phần Decision), `.superpowers/agents/m3-final-review.md` mục "M5 (admin)", mục **"Kết quả M4" → "Chuyển sang M5"** của roadmap (bắt buộc), và `.superpowers/agents/m5-planner-rulings.md` (ruling của controller cho bản plan đầu). **Thứ tự chạy: M6 (hero) chạy TRƯỚC M5** (ruling controller).

- **Mọi loader và action dưới `/admin` gọi `await requireAdmin(request)` ở dòng đầu; action gọi nó TRƯỚC `readForm`.** Action thường dùng `readForm(request)` (16KB); form sản phẩm dùng `readForm(request, PRODUCT_FORM_BYTES)` (11MB).

## Quyết định (Decision) ở những chỗ spec để ngỏ

1. **Decision: cổng quản trị hai lớp.** Layout `/admin` có `middleware` gọi `requireAdmin` (spec "layout + middleware"; nó chặn cả action con và request `.data` của fetcher: spike 1), **và** loader/action con nào cũng tự gọi `requireAdmin` (yêu cầu của roadmap; test gọi thẳng loader/action không đi qua middleware; route con sau này quên một lớp vẫn còn lớp kia). Action gọi `requireAdmin` **trước** `readForm`: khách không làm server đọc 6MB body (test bằng stream đếm lần đọc). Một test hợp đồng (`expectAdminOnly`) chạy cho mọi loader/action admin: chưa đăng nhập → `/login?redirectTo=…`, khách → 403.
2. **Decision: mỗi dòng đơn có MỘT nút tiến đúng một bước** ("Soạn hàng" → "Bắt đầu giao" → "Đã giao xong") + "Huỷ đơn", không có ô chọn trạng thái tự do. Form chỉ gửi `intent`, `id`, `from` (trạng thái đang thấy); đích luôn là bước kế tiếp của `from` (`NEXT_STATUS`), nên không thể nhảy lùi hay nhảy cóc, và cột `*_at` luôn được ghi theo thứ tự. Bấm 2 lần, hai máy cùng bấm, hay đơn vừa bị khách huỷ: lần sau trả "stale" (200 + lời nhắn, để RR tải lại trạng thái mới; RR bỏ revalidate khi action ≥400).
3. **Decision: đơn online khách chưa trả (chờ hoặc lỗi) → "Soạn hàng" chuyển đơn sang COD trong cùng câu UPDATE** (có hộp xác nhận "Khách chưa trả online. Soạn hàng và chuyển đơn … sang thu tiền khi giao (COD)?"), thay vì chặn. Lý do: chặn thì chủ shop chỉ còn cách huỷ (kể cả khi đã gọi khách và khách đồng ý trả tiền mặt), và kịch bản pitch "đặt online → thanh toán lỗi → admin xử lý" bị kẹt. Câu UPDATE có điều kiện `paymentStatus IN (unpaid, failed)`, nên khách trả tiền đúng lúc đó thì câu này không khớp: không bao giờ xoá một lần trả tiền (test lặp 10 lần chạy song song). Sau đó cổng giả lập đóng (`setOnlinePayment` cần `pending`), trang khách ghi "Trả tiền mặt khi nhận hàng".
4. **Decision: admin huỷ được đơn ở `pending`, `preparing`, `shipping` (hàng quay về kho nên hoàn kho cả ba), không huỷ được `done`.** Dùng lại `cancelOrder(orderId, now, from)` (tham số mới `from`, mặc định `"pending"` như khách). Đơn đã trả online bị huỷ giữ `paymentStatus = paid`; nhãn "Đã trả online · cần hoàn tiền (DEMO)" (admin) và "Tiền demo sẽ được hoàn cho bạn." (khách, M3) suy ra từ `cancelled + paid`: không thêm enum/cột.
5. **Decision: `/admin/orders/:code`** (spec ghi `:id`): giá trị là mã đơn DH… để dùng lại `getOrder(code)` + `toOrderView` của M4 và trùng mã khách đọc qua điện thoại. Đổi trạng thái ở trang chi tiết gửi về chính action của `/admin/orders` (một action duy nhất). **`/admin/products/:id`**: `:id` là id số, riêng `new` là trang thêm (một module cho cả `products/new` và `products/:id` của spec).
6. **Decision: chống cache ảnh cũ bằng phiên bản trong key**: mỗi lần admin tải ảnh, `Product.images[0] = "products/<slug>?v=<Date.now() base36>"`; `uploadUrl` tách `?v=` ra cuối URL (`/uploads/products/<slug>-640.webp?v=…`), tên file trên đĩa không đổi. Không thêm cột. Seed giữ nguyên key có `?v=` (không thì `npm run setup` chạy lại sẽ đưa URL về bản không phiên bản mà trình duyệt đã cache ảnh seed). `/uploads` thêm `X-Content-Type-Options: nosniff`.
7. **Decision: gia cố `saveSquareImage` (hợp đồng M0, chữ ký giữ nguyên)**: ném lỗi nếu `name` không khớp `IMAGE_NAME` (slug: chống path traversal ở chính hàm dùng chung, không chỉ ở form); `limitInputPixels = 50 triệu` (ảnh 48MP của điện thoại vẫn qua; bom 16000² bị chặn); **cắt vuông ở độ phân giải gốc trước** (`resize(side, side, cover + attention)` với `side` = cạnh ngắn), rồi mới đưa về 1080, với bản trung gian là **điểm ảnh thô** (`raw()`): không bao giờ phóng to trước khi cắt (ảnh dài 10×30000 qua mọi kiểm tra vì chỉ 0,3MP, nhưng `cover` 1080 thẳng phóng nó thành 1080×3,24 triệu điểm: >120s, 8,7GB RAM; cổng plan M5), và 6 biến thể không thành bản sao lossy lần hai (`.toBuffer()` không định dạng ra JPEG q80); mã hoá xong cả 6 biến thể trong bộ nhớ rồi mới ghi (ảnh hỏng giữa chừng không để lại bộ file nửa cũ nửa mới). Seed dùng chung hàm này, kết quả như cũ.
8. **Decision: upload đi qua `readForm(request, PRODUCT_FORM_BYTES = 11MB)`**: đọc theo luồng, dừng ở 11MB (413), rồi `new Response(blob).formData()` tách multipart thành `File` (spike 5). Ảnh **≤10MB** (`MAX_IMAGE_BYTES` trong `config.ts`; cổng plan M5 thay đổi 5: ảnh điện thoại 24–50MP đổi sang JPEG thường 5–10MB, và chủ shop không thu nhỏ ảnh được trên điện thoại; DoD chỉ đòi ảnh 5MB chạy được, không đặt trần). Form kiểm ngay trên máy: chọn ảnh >10MB thì báo dưới ô và khoá nút, không gửi 11MB đi. Body >11MB vẫn tới được server (không JS, gửi thẳng) thì action bắt 413 và trả lỗi ngay ở ô ảnh (status 413), không phải trang lỗi. Giải mã vẫn có trần `MAX_INPUT_PIXELS`. `ponytail:` body nằm trọn trong RAM (≤11MB/lần, một chủ shop); đọc theo luồng ra file tạm nếu nhiều admin cùng tải ảnh lớn.
9. **Decision: chỉ nhận JPEG/PNG/WebP**, kiểm theo thứ tự trước khi giải mã: cỡ ≤10MB → **byte đầu** (FF D8 FF / PNG 8 byte / RIFF…WEBP) → `sharp(…, { limitInputPixels }).metadata()` cùng định dạng. SVG (sharp đọc được SVG: spike 6), HTML, PDF, file đổi đuôi không bao giờ tới sharp. Ảnh gốc không lưu; chỉ 6 biến thể do sharp mã hoá lại được phát, với `Content-Type` từ regex của `/uploads` + `nosniff`. HEIC không nhận (sharp bản dựng sẵn không giải mã HEVC); `accept="image/jpeg,image/png,image/webp"` khiến iPhone tự đổi sang JPEG khi chọn ảnh.
10. **Decision: form sản phẩm là danh sách trắng** (zod): `name, categoryId, priceVnd, compareAtVnd, unit, netGrams, isWeighed, origin, shelfLife, storage, description, stock`; `isGiftBase`, `cutoutUrl`, `images`, `isActive`, `id`, `nameSearch` gửi kèm bị bỏ (test). `nameSearch = toSearch(name)` tính ở server. Giá bán ≥1.000₫; giá gốc trống hoặc **> giá bán** (roadmap M1; cũng chặn luôn "0₫ gạch" của cổng M2). Slug chỉ nhập lúc thêm (trống thì tạo từ tên), sau đó cố định (key ảnh); phải khớp `IMAGE_NAME`, ≤60 ký tự, **không kết thúc bằng `-cut`/`-cutout`** (tên file ảnh bổ đôi/tách nền của sản phẩm khác: `xoai-cat-hoa-loc-cut` sẽ ghi đè ảnh bổ đôi của xoài). Danh mục phải còn trong DB.
11. **Decision: thêm sản phẩm ghi DB trước (ở trạng thái ẩn), ảnh sau, rồi mới bật bán**: slug trùng (P2002) → lỗi ở ô slug và **không chạm ảnh** của sản phẩm đang dùng slug đó (test kiểm `mtime`). Dòng mới tạo với `isActive: false` và chỉ bật sau khi 6 biến thể đã ghi (gợi ý 1 của cổng plan): trong 2–6s mã hoá khách không thấy món chưa có ảnh và không ai bỏ được nó vào giỏ, nên ảnh hỏng → xoá dòng vừa tạo luôn an toàn (không khoá ngoại nào trỏ tới). Không chọn ảnh → ảnh tạm như seed (`placeholderImage`). **Sửa: ghi các ô → ghi file ảnh → chỉ khi file đã nằm trên đĩa mới đổi `?v=`** (cổng plan thay đổi 2: đổi URL trước thì trang nào render trong lúc mã hoá phát URL mới trỏ tới file cũ, trình duyệt cache ảnh cũ dưới URL mới 7 ngày). Ảnh hỏng khi sửa: URL cũ giữ nguyên, trỏ tới bộ file cũ còn nguyên (test).
12. **Decision: tồn kho sửa có điều kiện**: form gửi kèm `stockWas`; `updateMany WHERE id AND stock = stockWas`. Có đơn trừ kho trong lúc admin đang sửa thì không ghi đè (spec: "kho không được sai"), trả 409 + lời nhắn "hiện còn N", và `shouldRevalidate` tải lại loader để `stockWas` mang số mới (cùng cách checkout M3).
13. **Decision: "Xoá" = nút "Ngừng bán (xoá khỏi cửa hàng)"** (server cũng chặn: `setProductActive` chỉ đổi dòng `isGiftBase: false`, nên một POST lạc không ngừng bán được vỏ giỏ; gợi ý 2 của cổng plan) (có xác nhận; món có ảnh tách nền thì câu xác nhận nói thêm "Giỏ quà khách đang để trong giỏ hàng có món này cũng bị bỏ ra (khách phải xếp lại).": `bundleViews` bỏ cả dòng giỏ quà khi một thành phần ngừng bán, M4 Decision 9; mục tuỳ chọn của Kết quả M4) và "Bán lại". Vỏ giỏ quà không có nút này (ngừng bán vỏ giỏ làm mọi giỏ quà biến khỏi giỏ hàng, M4 Decision 9); `isGiftBase`/`cutoutUrl` không sửa được trong admin; tải ảnh không tạo ảnh tách nền (giỏ quà chỉ dùng 12 món có sẵn, bàn giao M4: `ponytail:`).
14. **Decision: giao diện quản trị riêng**: root `Layout` ẩn header tìm kiếm/giỏ, footer và drawer của khách khi đường dẫn là `/admin` hoặc `/admin/…`; layout admin có header gọn (logo, nhãn "Quản trị", nút "Xem cửa hàng", "Đăng xuất") và 2 tab "Đơn hàng" / "Sản phẩm" (`NavLink`, `aria-current`). Root loader trả thêm `user.isAdmin`; khi chủ shop đăng nhập, nút tài khoản ở header khách thành "Trang quản trị" (`ClipboardList`) dẫn tới `/admin/orders` (kịch bản pitch spec mục 1). `/admin` chuyển tới `/admin/orders`.
15. **Decision: 403 hiện ở boundary của root** (middleware ném lỗi trước khi loader nào chạy nên RR hiện boundary của route cao nhất có loader: spike 2): root `ErrorBoundary` có thêm nhánh 403 "Không có quyền / Bạn không có quyền vào trang quản trị." + link "Về cửa hàng". ## Spike findings (đã chạy thật ngày 15/10/2026, trong scratchpad `m5-spike/`)

**Toàn bộ code của plan này đã được dựng thử trong một bản sao project ở scratchpad** (bản đầu: project + plan M4 áp bằng script; **đồng bộ lại sau khi M4 vào project thật**, 15/10): chép project thật (sau M4: vitest 266, e2e 30), DB riêng `chosang_m5spike` + `chosang_m5test` (sửa `TEST_DB` trong bản sao; **không bao giờ** chạy test vào `chosang_test`/`chosang`), cổng 3510; đã xoá DB sau đó. Kết quả trên cây thật: `npm run typecheck` sạch; vitest **330/330** (266 + 64); Playwright **33/33** trên bản build production (30 + 3); con số này là sau lượt sửa của cổng plan M5 (`.superpowers/agents/m5-plan-review.md`: 5 thay đổi bắt buộc + gợi ý 1, 2, 3, 5); JS route đầu `/` **128.042** byte gzip (M4 thật: 127.207, +835 byte: manifest 5 route admin + `isAdmin` ở header; trần 133.120). Mọi patch được sinh bằng `diff -u` giữa cây thật và bản thử, rồi trích lại từ chính văn bản plan và áp `patch -p1` theo thứ tự task lên một bản sao sạch của cây thật: kết quả trùng từng byte với bản thử. Khi đồng bộ, chỉ patch `prisma/seed.ts` không khớp (M4 thêm nhánh vỏ giỏ: Decision 24); các patch khác chỉ lệch dòng.

1. **Loader của layout KHÔNG bảo vệ action con.** Layout `/admin` chỉ có loader `requireAdmin`, action `/admin/orders` không tự kiểm: `curl -X POST` bằng cookie **khách** vào `/admin/orders` (document) và `/admin/orders.data` (kiểu fetcher) đều 200, đơn chuyển sang `preparing` rồi bị huỷ. Thêm `middleware` vào layout: cùng hai POST đó → **403**, khách chưa đăng nhập POST `.data` → redirect `/login`; admin → 200. (RR 8 middleware không cần cờ `future`.)
2. **Middleware ném lỗi trước `next()`** (403 của khách) hiện `ErrorBoundary` của **root** (route cao nhất có loader, đúng docs `how-to/middleware.md` "next() and Error Handling"), không phải boundary của layout admin: lần chạy e2e đầu thấy "Có lỗi xảy ra" thay vì "Không có quyền" → Decision 15.
3. **RR 8 không bỏ `.data` khỏi `request.url`** (cờ v7 `v8_passThroughRequests` nay là mặc định): GET `/admin/orders.data` khi chưa đăng nhập trả redirect `/login?redirectTo=%2Fadmin%2Forders.data`. Sau khi sửa `requireAdmin` → `/login?redirectTo=%2Fadmin%2Forders` → Decision 16.
4. **RR 8.4 tự chặn POST khác origin vào action của route có UI** (400 "Bad Request" trước code của mình) khi gọi qua HTTP; `readForm` vẫn trả 403 ở mức unit (test CSRF gọi thẳng action) và cho resource route.
5. **Multipart không cần thư viện:** `readForm` (đọc theo luồng có trần, rồi `new Response(blob, { headers: { "Content-Type": type } }).formData()`) trả `File` đúng cỡ trong Node 22.22 cho request tạo từ `FormData` (vitest) và từ form trình duyệt (e2e, ảnh ~5MB). Body 11,5MB (trần 11MB) → `readForm` ném 413 → action trả `{ errors: { image } }` status 413.
6. **sharp 0.35.5:** `sharp(buf, { limitInputPixels: 50_000_000 }).metadata()` trên PNG 776KB khai 16000×16000 ném "Input image exceeds pixel limit" ngay (0ms, chưa giải mã); không có trần thì `metadata()` trả 16000×16000. SVG được đọc với `format: "svg"` (nên phải chặn bằng byte đầu trước); chuỗi chữ → "unsupported image format"; JPEG + HTML nối đuôi đọc thành `jpeg` (an toàn vì luôn mã hoá lại); JPEG bị cắt còn 200KB **qua được `metadata()`** nhưng hỏng khi giải mã (test createProduct "ảnh hỏng").
7. **Cắt ở độ phân giải gốc, trung gian thô (sửa theo cổng plan M5):** bản đầu (`cover` 1080 thẳng, `.toBuffer()` không định dạng) nhanh hơn 5,8s → 3,9s cho JPEG 5MB, nhưng tốc độ đó đến từ bản trung gian **JPEG q80** (lossy lần hai, làm mịn ảnh nhiễu), và PNG 10×30000 (2,3KB, 0,3MP) bị phóng thành 1080×3,24 triệu điểm: >120s, 8,7GB RAM (Consultant đo). Bản sửa: `metadata()` lấy cạnh ngắn → `rotate().resize(side, side, cover + attention).raw()` → `sharp(raw).resize(1080, 1080).raw()` → 6 lần mã hoá. Đo lại trên bản thử: ảnh 10×30000 xong 6 biến thể dưới 5s (test), JPEG 5MB ≈6s (test có timeout 30s), PNG 4 kênh giữ alpha. AVIF chiếm phần lớn thời gian, nút "Đang lưu…" che khoảng chờ. **Không chạy pipeline cũ trên ảnh 10×30000** (8,7GB, có thể làm treo máy).
8. **Ảnh thử ~5MB tất định đủ dùng:** `sharp({ create: { width: 3000, height: 2340, channels: 3, background: "#808080", noise: { type: "gaussian", mean: 128, sigma: 40 } } }).jpeg({ quality: 92 })` ≈ 5,01MB (≤ 5MiB = 5.242.880). Kiểu TS của sharp bắt buộc `background` khi có `noise`.
9. **Prisma 7.10 `updateMany` có điều kiện:** hai `advanceOrder(id, "pending")` song song → `["advanced", "stale"]`; khách trả tiền đúng lúc admin bấm (chạy song song ×10): không lần nào mất `paid` (có lần admin nhận "stale" và bấm lại là qua). export function AdminOrderActions({ id, code, status, awaitingPayment }: { id: number; code: string; status: OrderStatus; awaitingPayment: boolean }) {
  const fetcher = useFetcher<{ ok: true; message: string } | { ok: false; error: string }>();
  const advance = ADVANCE[status];
  if (!advance) return null; // đã giao / đã huỷ: không còn thao tác
  const busy = fetcher.state !== "idle";
  const result = fetcher.data;
  return (
    <fetcher.Form
      method="post"
      action="/admin/orders"
      onSubmit={(e) => {
        const submitter = (e.nativeEvent as SubmitEvent).submitter as HTMLButtonElement | null;
        const ask =
          submitter?.value === "cancel"
            ? `Huỷ đơn ${code}? Hàng sẽ được trả về kho.`
            : awaitingPayment && `Khách chưa trả online. Soạn hàng và chuyển đơn ${code} sang thu tiền khi giao (COD)?`;
        if (ask && !confirm(ask)) e.preventDefault();
      }}
    >
      <input type="hidden" name="id" value={id} />
      <input type="hidden" name="from" value={status} />
      <div className="flex gap-2">
        <button
          name="intent"
          value="advance"
          disabled={busy}
          className="inline-flex min-h-11 flex-1 items-center justify-center rounded-full bg-ink px-4 font-display font-extrabold text-surface transition-colors duration-150 ease-snappy hover:bg-ink/85 disabled:opacity-60 sm:flex-none"
        >
          {busy && fetcher.formData?.get("intent") === "advance" ? "Đang lưu…" : awaitingPayment ? `${advance} (COD)` : advance}
        </button>
        <button
          name="intent"
          value="cancel"
          disabled={busy}
          className="inline-flex min-h-11 items-center justify-center rounded-full border border-ink px-4 transition-colors duration-150 ease-snappy hover:bg-ink/5 disabled:opacity-60"
        >
          Huỷ đơn
        </button>
      </div>
      {result && !result.ok && (
        <p role="alert" className="mt-2 flex items-start gap-1.5 text-sm text-danger">
          <CircleAlert aria-hidden className="mt-0.5 size-4 shrink-0" />
          {result.error}
        </p>
      )}
    </fetcher.Form>
  );
}

  .refine((s) => !/-cut(?:out)?$/.test(s), "Đường dẫn không được kết thúc bằng “-cut” hay “-cutout” (tên dành cho ảnh).");

/** Form sản phẩm → các ô đã kiểm. `slug` chỉ có khi tạo mới (sau đó cố định: key ảnh `products/<slug>` không đổi). */
export function parseProductForm(
  form: FormData,
  mode: "create" | "update",
): { ok: true; data: ProductFields; slug: string } | { ok: false; errors: ProductErrors } {
  const value = (key: string) => {
    const v = form.get(key);
    return typeof v === "string" ? v : "";
  };
  const parsed = productSchema.safeParse(Object.fromEntries(Object.keys(productSchema.shape).map((k) => [k, value(k)])));
  const errors: ProductErrors = parsed.success ? {} : z.flattenError(parsed.error).fieldErrors;
  let slug = "";
  if (mode === "create") {
    const s = slugSchema.safeParse(value("slug").trim() || slugify(value("name")));
    if (s.success) slug = s.data;
    else errors.slug = [s.error.issues[0].message];
  }
  return parsed.success && !errors.slug ? { ok: true, data: parsed.data, slug } : { ok: false, errors };
}

const SIGNATURE = {
  jpeg: (b: Buffer) => b[0] === 0xff && b[1] === 0xd8 && b[2] === 0xff,
  png: (b: Buffer) => b.subarray(0, 8).equals(Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a])),
  webp: (b: Buffer) => b.toString("latin1", 0, 4) === "RIFF" && b.toString("latin1", 8, 12) === "WEBP",
};

/**
 * Ảnh tải lên → Buffer đã kiểm, hoặc null khi không chọn ảnh. Chặn theo thứ tự, trước khi giải mã:
 * cỡ file ≤10MB → byte đầu đúng JPEG/PNG/WebP (SVG, HTML, PDF, file đổi đuôi bị loại, không bao giờ tới sharp)
 * → `metadata()` của sharp cùng định dạng và ≤50 triệu điểm ảnh (bom giải nén). Ảnh gốc không bao giờ được lưu
 * hay phát lại: chỉ 6 biến thể sharp mã hoá lại.
 */
export async function checkImage(entry: FormDataEntryValue | null): Promise<{ ok: true; image: Buffer | null } | { ok: false; error: string }> {
  if (!(entry instanceof File) || entry.size === 0) return { ok: true, image: null };
  if (entry.size > MAX_IMAGE_BYTES) return { ok: false, error: "Ảnh tối đa 10MB, bạn chọn ảnh nhỏ hơn giúp mình nhé." };
  const image = Buffer.from(await entry.arrayBuffer());
  const kind = (Object.keys(SIGNATURE) as (keyof typeof SIGNATURE)[]).find((k) => SIGNATURE[k](image));
  const notImage = { ok: false, error: "Chỉ nhận ảnh JPG, PNG hoặc WebP." } as const;
  if (!kind) return notImage;
  try {
    const meta = await sharp(image, { limitInputPixels: MAX_INPUT_PIXELS }).metadata();
    return meta.format === kind ? { ok: true, image } : notImage;
  } catch (error) {
    const tooLarge = error instanceof Error && error.message.includes("pixel limit");
    return { ok: false, error: tooLarge ? "Ảnh quá lớn (tối đa 50 triệu điểm ảnh), bạn thu nhỏ ảnh rồi thử lại nhé." : "Ảnh bị hỏng, không đọc được." };
  }
}

const IMAGE_BROKEN = "Ảnh bị hỏng, không đọc được.";
// Mã phiên bản mới cho mỗi lần tải ảnh: URL đổi nên cache 7 ngày của /uploads không giữ ảnh cũ (roadmap M1 → M5)
const versioned = (slug: string) => `products/${slug}?v=${Date.now().toString(36)}`;

const fieldsData = (d: ProductFields) => ({ ...d, nameSearch: toSearch(d.name) });
const categoryExists = async (id: number) => (await db.category.count({ where: { id } })) === 1;
const CATEGORY_MISSING: ProductErrors = { categoryId: ["Danh mục không còn, bạn chọn lại giúp mình nhé."] };

/**
 * Thêm sản phẩm. Ghi DB TRƯỚC (slug trùng → lỗi field, không ghi đè ảnh của sản phẩm đang dùng slug đó), ở trạng thái
 * ẨN (`isActive: false`), rồi ghi 6 biến thể ảnh (không có ảnh thì dùng ảnh tạm như seed), xong mới bật bán. Trong 2–6s
 * mã hoá, khách không thấy món chưa có ảnh và không ai bỏ được nó vào giỏ, nên ảnh hỏng thì xoá dòng vừa tạo luôn an toàn.
 */
export async function createProduct(
  data: ProductFields,
  slug: string,
  image: Buffer | null,
): Promise<{ ok: true; id: number } | { ok: false; errors: ProductErrors }> {
  if (!(await categoryExists(data.categoryId))) return { ok: false, errors: CATEGORY_MISSING };
  let id: number;
  try {
    ({ id } = await db.product.create({ data: { ...fieldsData(data), slug, images: [versioned(slug)], isActive: false }, select: { id: true } }));
  } catch (error) {
    if (error instanceof Prisma.PrismaClientKnownRequestError && error.code === "P2002") {
      return { ok: false, errors: { slug: ["Đường dẫn này đã có sản phẩm khác dùng, bạn đổi giúp mình nhé."] } };
    }
    throw error;
  }
  try {
    await saveSquareImage(image ?? placeholderImage(data.name, "#F3F0F7"), OUT_DIR(), slug);
  } catch {
    await db.product.delete({ where: { id } }); // dòng ẩn vừa tạo: chưa giỏ nào, đơn nào trỏ tới
    return { ok: false, errors: { image: [IMAGE_BROKEN] } };
  }
  await db.product.update({ where: { id }, data: { isActive: true } });
  return { ok: true, id };
}

/**
 * Sửa sản phẩm. Tồn kho chỉ ghi khi DB vẫn còn đúng số admin đã thấy (`stockWas`): trong lúc admin sửa mà có đơn
 * trừ kho thì không ghi đè mất phần đã bán (spec: kho không được sai). Ảnh mới: ghi các ô → ghi file ảnh → CHỈ KHI
 * file đã nằm trên đĩa mới đổi `?v=` (cổng plan M5: đổi URL trước thì trang nào render trong 2–6s mã hoá sẽ phát URL
 * mới trỏ tới file cũ, và trình duyệt cache ảnh cũ dưới URL mới 7 ngày). Ảnh hỏng: URL cũ giữ nguyên, file cũ còn nguyên.
 * Giữ ảnh bổ đôi `images[1]` nếu có.
 */
export async function updateProduct(
  id: number,
  stockWas: number,
  data: ProductFields,
  image: Buffer | null,
): Promise<{ ok: true } | { ok: false; errors: ProductErrors }> {
  const current = await db.product.findUnique({ where: { id }, select: { slug: true, images: true } });
  if (!current) return { ok: false, errors: { form: ["Sản phẩm không còn."] } };
  if (!(await categoryExists(data.categoryId))) return { ok: false, errors: CATEGORY_MISSING };
  const { count } = await db.product.updateMany({ where: { id, stock: stockWas }, data: fieldsData(data) }); // chưa đụng ảnh
  if (count === 0) {
    const now = await db.product.findUnique({ where: { id }, select: { stock: true } });
    return { ok: false, errors: { stock: [`Tồn kho vừa thay đổi (có đơn mới hoặc ai đó vừa sửa), hiện còn ${now?.stock ?? 0}. Bạn kiểm lại rồi lưu nhé.`] } };
  }
  if (image) {
    try {
      await saveSquareImage(image, OUT_DIR(), current.slug);
    } catch {
      return { ok: false, errors: { image: [IMAGE_BROKEN] } };
    }
    // URL chỉ đổi sau khi byte mới đã nằm trên đĩa
    await db.product.update({ where: { id }, data: { images: [versioned(current.slug), ...current.images.slice(1)] } });
  }
  return { ok: true };
}

/**
 * "Xoá" = ngừng bán (soft delete, spec + roadmap M3 → M5): đơn cũ giữ khoá ngoại và bản chụp; "Bán lại" bật lại.
 * Vỏ giỏ quà không bao giờ (Decision 13): ngừng bán nó làm mọi giỏ quà biến khỏi giỏ hàng của khách; POST lạc cũng không được.
 */
export async function setProductActive(id: number, isActive: boolean): Promise<boolean> {
  const { count } = await db.product.updateMany({ where: { id, isGiftBase: false }, data: { isActive } });
  return count === 1;
}

function productId(param: string): number | "new" {
  if (param === "new") return "new";
  if (!/^\d{1,9}$/.test(param)) throw new Response("Không tìm thấy sản phẩm", { status: 404 });

}

const done = async (request: Request, to: string, toast: string) => {

export async function action({ request, params }: Route.ActionArgs) {
  await requireAdmin(request); // TRƯỚC khi đọc body: không nhận 11MB của người không phải admin
  const id = productId(params.id);
  let form: FormData;
  try {
    form = await readForm(request, PRODUCT_FORM_BYTES); // Origin + trần 11MB đọc theo luồng (mặc định 16KB thì ảnh nào cũng 413)
  } catch (error) {
    if (error instanceof Response && error.status === 413) return data({ errors: { image: [TOO_BIG] } as ProductErrors }, { status: 413 });
    throw error;
  }
  const intent = form.get("intent");
  if (id !== "new" && (intent === "deactivate" || intent === "activate")) {
    if (!(await setProductActive(id, intent === "activate"))) throw new Response("Không tìm thấy sản phẩm", { status: 404 });
    return done(request, `/admin/products/${id}`, intent === "activate" ? "Sản phẩm đã bán lại" : "Đã ngừng bán sản phẩm");
  }

  const parsed = parseProductForm(form, id === "new" ? "create" : "update");
  const image = await checkImage(form.get("image"));
  if (!parsed.ok || !image.ok) {
    const errors: ProductErrors = { ...(parsed.ok ? {} : parsed.errors), ...(image.ok ? {} : { image: [image.error] }) };
    return data({ errors }, { status: 400 });
  }
  if (id === "new") {
    const created = await createProduct(parsed.data, parsed.slug, image.image);
    if (!created.ok) return data({ errors: created.errors }, { status: 400 });
    return done(request, `/admin/products/${created.id}`, "Đã thêm sản phẩm");
  }
  const stockWas = Number(form.get("stockWas"));
  if (!Number.isInteger(stockWas)) return data({ errors: { form: ["Trang đã cũ, bạn tải lại giúp mình nhé."] } as ProductErrors }, { status: 400 });
  const updated = await updateProduct(id, stockWas, parsed.data, image.image);
  // 409: tồn kho vừa đổi → tải lại loader để `stockWas` mang số mới (RR bỏ revalidate khi ≥400, như checkout M3)
  if (!updated.ok) return data({ errors: updated.errors }, { status: updated.errors.stock ? 409 : 400 });
  return done(request, `/admin/products/${id}`, "Đã lưu sản phẩm");
}
